1. What Runs 100% Live Over `gemini-4-argon` (`engine/argon_client.py`) Interactions API

Every step makes real, unmocked calls to client.interactions.create(...):

  • Step 1 (`POST /ledger`): Sends the full repository + compiler diagnostics live to model="gemini-4-argon" (plus 4 concurrent model="gemini-3.8-flash" leaf subagents). Returns a live server-side interaction.id and structured InterfaceLedgerSchema JSON.
  • Step 3a (`POST /baseline`): Makes 6 live parallel calls to model="gemini-4-argon" (1 isolated file per call with no shared cross-file context) and writes the generated code to runs/<session_id>/baseline_ws/.
  • Step 3b (`POST /argon`): Calls model="gemini-4-argon" live with previous_interaction_id=session.ledger_interaction_id (reusing the server-side cached repo state from Step 1) to synthesize all mutable files in runs/<session_id>/argon_ws/.
  • Autonomous Repair Loop (Turn 2+): If the compiler or fuzzer catches any error, the exact compiler traceback is sent live back to `gemini-4-argon` via previous_interaction_id until all checks pass.
2. How Local Compilers & Fuzzers Connect (`engine/verifiers.py`) Real Host Toolchain

Our Python orchestrator executes real local compiler, test, and fuzzer binaries via subprocess.run(...) immediately after each gemini-4-argon turn and feeds the real stdout/stderr back into the next previous_interaction_id turn:

  • Linux & Git C (`linux_git_c_hardening`): Compiles with clang -Wall -Wextra -Werror and runs the 5-test C suite + 0xAA stack-poisoning padding leak detector.
  • C-to-Safe-Rust (`c_to_rust_framecodec`): Runs cargo test + the 107-check C-vs-Rust Differential Fuzzer (fuzz_harness.py against libframecodec.dylib).
  • Apache Superset TS 6.0 (`superset_ts6`): Runs real npx tsc --noEmit with strict TS 6.0 flags + behavioral runtime suite.
  • Ray / Pydantic v2 (`py_v1_to_v2`): Runs real mypy --strict + pytest -W error (failing on any v1 deprecation warning).
Why this hybrid design? Using structured JSON output (response_format) + deterministic host verification between previous_interaction_id turns guarantees every run executes the exact compiler/fuzzer check in ~1 second without extra round-trip tool-call latency.
